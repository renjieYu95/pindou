# 首版技术设计

## 数据流

用户选择图片 → Canvas 解码 → 旋转/裁剪/填充 → 最多 512×512 工作画布 → 按格子采样 → Lab 色差匹配 → 限色色板 → 可编辑色号矩阵 → 预览、统计、存储、导出。

微信使用原生 JavaScript，避免需要额外编译流程。`core/` 与 `data/` 使用 UMD 模块包装，在微信侧通过 `require` 使用，在浏览器侧加载同一份源文件。界面和存储适配器分开，两端不声称具有完全相同的系统能力。

## 配色与透明度

工作画布每颗豆子使用 4×4 像素。平均采样按 alpha 加权，隐藏 RGB 不污染透明边缘；平均不透明度低于 0.35 的区域为空格。像素画模式取格子中心点。白底模式先合成白色再配色。

颜色转为 CIELAB，使用 ΔE76 的平方距离。先映射到固定参考色卡，按已使用颜色的频次加权、依色差分散选出有限颜色，再进行四轮加权中心优化，中心每次都映射回真实色卡。最终所有像素重新映射到该子集。流程确定性，无随机抖动。颜色上限可能未用满，例如原图颜色少或多个中心合并。

可选杂点清理仅处理四邻域完全同色且与中心格 Lab 距离较小的孤点，透明格和高对比点保留。不是图像语义识别，不承诺保留所有照片细节。

## 工程模型

```js
{
  version: 1,
  id: "p…",                  // 保存后分配
  title: "林间小兔",
  width: 48,
  height: 48,
  cells: ["G15", null, …],    // 行优先；null 为空格
  palette: { id, name, version, source, note, colors: [{code, name, hex}] },
  settings: { maxColors, sampling, background, denoise, fit, rotation, cropZoom, offsetX, offsetY },
  createdAt: 0,
  updatedAt: 0
}
```

色卡完整快照跟随工程保存，后续更新默认色卡不会改变已保存作品。导出和计数只读取当前矩阵，手动编辑后不使用旧的统计缓存。

## 编辑与撤销

一次触摸笔划内合并每格的初始值与最终值，保存差量补丁。拖动采样间使用整数直线算法补齐格子。单次整色替换也是一个补丁。撤销栈上限 60 步；重新生成/打开其他作品会重置撤销历史。

## 存储与导出

微信先写入新的独立 JSON 文件，再更新索引，成功后移除旧文件；索引写入失败会保留原作品并清理新文件。浏览器通过单次 localStorage 写入完整作品列表，存储失败提示工程备份。

施工图每页最多 48×48 格，每格 32 像素，并使用绝对行列编号。清单每页最多 48 色。最大页面小于 2048×2048，以减少手机上的 Canvas 内存需求；每页依次绘制和导出，不同时创建多个大画布。导出所有 PNG 后由微信图片预览提供长按保存。

## 首版边界

- 最大 128×128，暂不支持更大图纸、手动自定义高宽两个独立数值或任意多边形裁剪。
- 自动画面比例受高度 128 的限制；使用完整显示或裁剪填满保证不拉伸。
- 本地文件解码前检查尺寸，仍需在低内存机型验证平台解码峰值。
- 计算在页面逻辑线程进行；后续可迁移 Worker。桌面计时不代表手机性能。
- 无网络上传、无账号、无后台服务、无自动抠图。
- 关闭/清理小程序前应显式保存；当前编辑状态不做自动云备份。
